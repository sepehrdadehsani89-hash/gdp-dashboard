# 06 — INTELLIGENT BLUETOOTH BATTERY ESTIMATION

Add a sophisticated accessory-runtime estimation engine.

## Goal

When the user asks:

"How much longer can my headphones play?"

JARVIS should answer using real data when possible.

## Data sources

Investigate:

1. Battery values exposed by the device through supported Bluetooth profiles.
2. Supported Bluetooth Low Energy Battery Service characteristics.
3. Available public Android battery reporting mechanisms.
4. Manufacturer-supported integrations.
5. User-authorized accessory specifications.
6. Historical observed battery usage collected by JARVIS with permission.

## Estimation logic

When reliable data exists:

- Read current percentage.
- Check whether the accessory is actively in use.
- Determine the relevant usage mode.
- Check available recent discharge history.
- Use an appropriately smoothed estimate.
- Consider whether the accessory's stated runtime is available and applicable.
- Report an approximate remaining time.
- Display uncertainty when necessary.

## Critical rules

Do not estimate playback time solely from battery percentage without a meaningful usage model.

Do not assume every headset lasts the same number of hours.

Do not assume an accessory is playing audio just because it is connected.

Do not invent battery percentages when the device does not expose them.

If battery percentage is available but runtime estimation is not:

"Your headphones are at sixty-eight percent, sir. A reliable playback-time estimate isn't available."

If neither measurement is available:

"Your headphones are connected, sir, but this device isn't reporting its battery information."

This is preferable to false precision.
