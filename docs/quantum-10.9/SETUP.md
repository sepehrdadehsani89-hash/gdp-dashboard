# Quantum Core beta setup

Keep original Jarvis7.0 installed and its data intact. This APK can update only the newer retained reinstall signing line, such as 10.4 reinstall. An original-signature7.0 update remains blocked without its private signing key. Nothing in this upgrade uninstalls or changes your phone.

Open Settings → Capabilities to reach the shared Quantum Core screens. Control Center is available there. Voice/touch controls use the same new operation adapters. Tap optional permissions only for features you want. Bluetooth enable uses Android confirmation; disabling uses Android settings. Torch requires camera permission and real callback confirmation. Radio panels do not establish that a setting changed; actual states are re-read after return. Available audio outputs do not prove active playback routing. Accessory query distinguishes paired and profile-connected devices; explicit BLE reads can fail when the accessory does not expose Battery Service. Optional forecast sampling requires confirmation of continuous playback/no charging and sufficient real observations; missing evidence means no estimate.

Open Settings → Output voice. Both voices are Fish Audio (confirmed by the owner). Choose English or Spanish. English starts at05b36da8574341d0803391491850db20 and remains editable. Spanish is fixed toae74d1059517440aa6e5d2d50598d179. Enter a matching Fish API key privately on the phone, confirm the service/cost notice, play the actual preview, then explicitly enable. A successful preview needs real account access. Never paste keys in chat or commit them. Spanish does not fall back to a system, neural, OpenAI or different Fish speaker. Without configuration/connectivity it remains readable text with an error. Private replies stay local unless the separate private-speech sharing option is enabled; this sharing is optional per-language and can be revoked immediately. No Android credential values are collected.

Voice Lab provides explicitly tapped local background/wake samples and actual RMS/dBFS/clipping, available session effects, current input route and Vosk results when the selected model is installed. Raw calibration buffers are erased. AEC/NS availability does not establish recognition accuracy or acoustic barge-in. There is no automatic microphone enable or model download. Sensitivity changes apply on recorder restart. Speaker greetings use a current conservative match from opted-in, consented profiles; cold/missing/uncertain or locked-device matches remain neutral, and voice never authenticates private access.

Battery shows exact level colors and controls default-on voice/critical alerts, volume, quiet hours and notifications. Safe spoken alerts need optional call-state permission, an idle audio session, no protected Android credential UI and appropriate sound settings. Android must keep the process alive; background delivery and audibility are not guaranteed. Percentage reservations prevent repeated scheduling after restart, not proof of hearing. Missed intermediate levels are never replayed.

Location supports current fixes and explicit address lookup, reviewed Home saving/replacement and saved destinations. “Where am I?” with location disabled asks before opening Android setup. After user action, the exact pending task resumes only within its expiry and current command generation. Stop/cancel/lock invalidates continuation. Maps URLs request navigation but do not prove the third-party Start button was pressed. Location providers/accuracy/network may prevent a fresh fix. Home by arbitrary typed address and full navigation-session control remain incomplete.

Routines reuse the existing checked engine with1–8 ordered supported steps, up to12 private routines. Supported examples: battery; time; weather in Quito; my calendar today; my tasks; open Spotify. Save and enable a routine explicitly, then test its exact trigger. Pending approval/ambiguous actions stop later steps; automatic continuation behind approval is not claimed. Routine definitions are not instructions from webpages or indexed documents.

Memory cards edit the original approved records, search lexically, pin/category and export selected approved cards through Android's file picker. Existing memory/history databases stay intact. Full semantic vector retrieval is not newly implemented. Old memory exports do not include every new feature store, voice key, model, history or signing identity.

Screen Security uses one Android-owned authentication to enable future unlock requests; there is no custom triple credential wizard. Every unlock remains Android's responsibility. Optional device administration requests force-lock only. “Shut down all systems” cancels Jarvis's own operations and requests authorized locking; it does not erase memories, power off Android or stop other apps.

See STATUS.md and PRESERVATION.md for incomplete20/50feature claims. This beta adds no payment collection or app subscription. Third-party services can still charge their own fees. Keep the retained signing backup and its separate unlock file privately outside this cloud workspace for future updates.
