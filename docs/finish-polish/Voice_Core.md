# Voice, deterministic answers and existing-core repairs

Implementation preserves the existing Vosk final-schema handling, ManagedMicrophone owner, greeting gate, conversation window, circular geometry, original rings/layout, center telemetry and licensed assets. No new Living Core feature or renderer was created.

- `WakePhraseMatcher.extractCommand(text, language, customPhrase = null)` adds “Jarvis, are you up?” and localized readiness variants, keeps same-utterance suffixes and existing wake phrases, matches whole prefixes, and supports an explicit optional validated 2–6-word phrase. `validCustomPhrase` rejects short/generic action/stop overrides. This is matching decoded text, not training a custom acoustic keyword model.
- `LocalVoiceQueries` adds known app identity and actual phone clock time zone while retaining the original time/date signature and device clock behavior. Time-zone text does not claim GPS location.
- `LocalKnowledge.answer(text, language)` resolves identity/time zone and bounded arithmetic without a gateway, network, model or invented confidence. Time/date continue through their existing device-format-aware handler. Arithmetic uses a small grammar, literal BigDecimal values, EN/ES operators/basic number words, parentheses, unary negatives, decimal numbers and percentages. There is no `eval`, generated code or arbitrary function execution. Divide-by-zero, malformed expressions and resource limits have explicit local feedback. Long division is labeled approximate; unknown or advanced mathematical requests remain available to existing model routing.
- The shared `ReactorPalette` now distinguishes electric-blue actual speaking from cyan idle and purple listening. Only the state mapping changed, without moving/scaling/replacing the core.
- Both renderers use a shared actual charging predicate, requiring a connected source, genuine charging and the existing enabled setting. A connected full but noncharging phone still has its existing full/PowerCore status and notice; it does not pretend to be actively charging. The wallpaper speaks “playback level unavailable” rather than labeling artificial decorative motion as measured audio.
- Battery center remains the existing real Android telemetry value (or unavailable marker). Visibility, surface, reduced-motion, power, thermal and playback-envelope policies were audited and preserved; no measured handset FPS or new capability is claimed.

`FinishPolishVoiceTest` adds 15 logical regressions, including 100 text wake trials, 30 conversation-window follow-up trials and 20 combined-prefix suffix trials. These are deterministic software loops, **not** 100 acoustic attempts, wake recognition rates or latency benchmarks. They cover custom phrases, injected-zone identity/time, arithmetic boundaries/injection protection and state color/charging semantics. An additional standalone compiler check executed 13 deterministic arithmetic examples using the actual source and JDK/Kotlin toolchain; the parent release pipeline runs the full Android JVM/lint/build checks separately.

Hardware acceptance remains NOT RUN: no Video6158 or physical Android device is available. The core/voice changes still require actual microphone, room-noise, accent, output-account, locked/background, charger-transition, FPS, thermal and battery measurements. Broader offline conversation continues to require a genuinely installed compatible existing local model; no weights were downloaded, fabricated or retrained for these deterministic handlers.
