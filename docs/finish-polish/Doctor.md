# System Doctor implementation

Files: `finishpolish/doctor/DoctorPolicy.kt`, `SystemDoctor.kt`, `SystemDoctorActivity.kt`; nine software policy regressions in `DoctorPolicyTest.kt`.

The read-only registry returns typed probes with owner, platform, sampling time, permission, certainty, severity, failure category, fixed privacy-safe evidence, reference and next step. Real observations cover microphone grant/lease/input/RMS, audio mode, speech-pack installation, selected/recognizer language mismatch, recent categorized ASR/backend/audio events, saved output-voice configuration presence, actual volume/Silent/DND, installed local-model record, fresh battery, memory/thermal, pairing presence, wallpaper frame counters/visibility, OS crash/ANR metadata where supported and shared action stages. Unknown accuracy, server access, acoustic playback, model throughput, clipping, actual wake confidence and hardware FPS are explicitly unmeasured. A stopped recorder or unselected wallpaper is not automatically declared broken. No automatic model loading, microphone test, permission change or network request runs during an ordinary scan.

The explicit paired connection probe is bounded to eight seconds and validates the existing pinned endpoint identity through its existing client. It does not prove bearer authorization or desktop action execution.

One approved repair is implemented: restore balanced sensitivity plus noise/echo-processing preferences. The screen first previews exact settings, risk, expected outcome, verification and rollback, then uses the existing Android credential authorization. It rejects a locked phone, active AI call/private recording, unapproved request, cooldown violation, corrupt history and three attempts within ten minutes. An encrypted last-known snapshot is verified before a synchronous settings commit. Readback must match all three fields. A slow/failed verification restores and checks pre-attempt settings. The reported success is **VERIFIED_SETTINGS_ONLY**, never a claim of repaired acoustic recognition or available hardware audio effects. Real voice testing remains necessary on the next capture.

Repair storage has a five-second deadline checked after Android's synchronous commit returns. Android disk I/O cannot be forcibly interrupted safely; the small transaction runs off the UI thread without cancellation so an Activity transition cannot leave an unverified half-transaction. No retry loop exists. Approved rollback reads and restores only those same three fields. Original model assets, speaker templates, keys, IDs, pairings, data exports and other settings are outside this repair.

Data additions: encrypted FeatureVault keys `doctor_attempts` (at most three operational timestamps) and `doctor_last_good` (versioned sensitivity/noise/echo baseline). No schema migration of prior data. Report/export is volatile operational metadata only, with an explicit Android share chooser; it contains no transcript, PCM, credential, saved voice ID, device address or raw exception trace.

Integration: Runtime `val doctor by lazy { SystemDoctor(context, this) }`; register the unexported `finishpolish.doctor.SystemDoctorActivity` and link it from existing Settings. Voice intent can call `doctor.explain(language == ES)` or show the panel. Shared `polishActions` journal records actual config execution/readback/failure; recipe execution of `doctor.balance` remains excluded by the central registry.

No physical microphone, renderer surface, real Fish account, Windows/macOS host or Android runtime test was executed by this module author. Root runs the combined build, lint and software tests. Video 6158 was absent, so no audio-specific root cause is claimed from it.
