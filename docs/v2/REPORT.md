# Jarvis 2.11.6 implementation and acceptance report

This is an update to the existing Android application, package `com.jarvis.next`, version code **23**, using the retained newer signing line. The existing HUD/core identity and prior capabilities remain. This release is a development milestone, not completion of all 1,500 requirements or a commercial certification.

[Download and measured build evidence](../../downloads/v2-2.11.6/README.md) · [Phone setup and acceptance](PHONE-GUIDE.md) · [Paired computer setup](../../companion/README.md) · [Architecture decision](ADR-001.md).

## Changes in this release

- **In-app AI calls:** “call me now,” “let's do a call,” and “call me” open one ringing call, with a top HUD banner, call screen and notification. Answer stops ringing, starts/reuses the existing exclusive microphone service, speaks a connection greeting, then opens command capture. End, decline, missed ringing, interrupted audio and bounded inactivity finish the call and restore the prior wake-listening choice. Old notification IDs cannot answer or end a new call. No phone number, carrier call, call log or telephone account is involved.
- **Dated check-ins:** editable, encrypted date/time requests, explicit exact/approximate scheduling, permission feedback and revision-bound cancellation. Due invitations can ring the same AI-call flow; they are not marked spoken merely because a notification appeared. Reboot restoration schedules future entries without starting a microphone.
- **Battery conversation at 20%:** a real observed threshold invites an AI call, with the current fresh battery reading on pickup. Existing quiet hours, volume, call safety, retry bounds and critical 3%/2%/1% alerts remain. Completed playback acknowledges an alert; charging/recovery rearms it.
- **Voice focus:** optional first-speaker focus seeds a temporary local embedding and suppresses uncertain/other-speaker PCM windows before recognition and silence detection. It reuses the existing recorder. Any-speaker mode becomes the requested default once; encrypted trained-owner templates and optional owner-only execution remain. Without the optional speaker model, ordinary recognition stays available and focus is reported unavailable. This cannot separate overlapping voices perfectly, guarantee speaker identity or unlock Android.
- **Speech and answers:** bounded handoffs coordinate greeting completion, capture, processing and speech. Calls have a longer bounded follow-up window; normal conversations retain their endpoint rules. Fixed public greeting audio can be warmed/cached to reduce pickup delay; private chat audio is not cached. Numeric ordinary questions reach the configured backend. Provider HTTP status, unavailable output, Silent/DND, interrupted audio and backend errors remain distinct from genuine recognition failures. Local time/date/battery use actual device readings; installed-app actions use existing supported handlers. No arbitrary unsupported action is fabricated.
- **Motion:** the existing core has continuous visible idle rotation/breathing, microphone/playback-driven state motion and adaptive frame targets. The repair screen checks Android's selected live-wallpaper component and actual rendering counters, opens its real picker and offers explicit restoration of app motion. Rendering failures recover with bounded backoff. Reduced motion, visibility, heat and battery limits remain respected. A static screenshot cannot animate.
- **Paired desktop milestone:** explicit QR/code approval on both ends, private-LAN HTTPS, pinned certificate, encrypted phone credentials, revocation, bounded requests, anti-replay and authenticated execution receipts. Only opening an isolated Chrome profile and Google search are allowed. Success requires an actually loaded permitted page, not just process launch. The cloud verified actual Chromium against controlled local pages; Windows/macOS source launchers and a manual native CI build recipe are included, without claiming native testing or a built EXE.

Existing charging/ETA/reminders, widgets, panels, private files access, local AI, editable Fish Audio voices, chat cleanup, approved short local summaries and protected lock actions remain. Fish voice IDs remain configurable. Gmail stays removed as previously requested. Voice similarity never bypasses Android credentials; phone-wide widget/files access remains subject to Android's real permissions and selection UI.

## What still requires hardware and accounts

No physical Android device is attached to this environment; the final ADB list is empty. **Zero Android runtime/instrumentation cases were executed.** The Redmi 9 microphone, room-noise endpoint accuracy, voice false accept/reject rate, Fish account/acoustic playback, audible latency, lock screen, OEM background restrictions, notification pickup, battery thresholds, Doze alarms, actual FPS and wallpaper picker all require phone acceptance. The new Canvas pixel-motion instrumentation test compiled only. No measured millisecond latency or 60-FPS guarantee is claimed.

The previous speaker host study used a verified model on synthetic fixtures, not human enrollment. Official Vosk model-host access was denied by environment policy, so no new cloud acoustic decoder benchmark was obtained. General answers require the configured secure AI service or an installed local model; this build does not create credentials, recover unavailable original keys or override provider quotas.

Use the [phone guide](PHONE-GUIDE.md), then repeat the complete interaction at least five times: one wake word → one greeting → ask the time → correct actual local time → another question without waking again → truthful answer/backend error, with the core moving. Repeat with screen locked, after background/foreground and after media playback. Then test ringing/Answer/End, decline, a missed call, end during speech, denied mic, unavailable voice, a dated check-in, and a real 20% discharge. Compare first-speaker focus on/off with a second person; test all failures without executing uncertain protected actions.

Install over a matching newer signing-line build. If Android rejects its certificate, keep the installed app and data; do not uninstall or clear data to force an update. No replacement Android signing key was generated or published.
