# ADR 001 — Extend the existing Android app with a bounded local companion

Status: implemented development milestone, with hardware/native release gates still open.

The existing app is Kotlin/Compose with local Vosk recognition, optional WeSpeaker similarity, existing Fish output and configured AI providers. It uses `com.jarvis.next` and the retained newer certificate. This release keeps that structure and its stored data instead of creating a new demo, account database or UI shell.

The first desktop slice uses a visible Python 3.11+ service on an explicitly chosen private IPv4 address, private HTTPS and a manually approved QR pairing exchange. Android validates the scanned certificate pin, certificate validity and hostname/SAN; trust changes are scoped to this client, not the system. Typed Chrome open/search commands include identity/session/device IDs, expiry, nonce, confirmation and idempotency keys. An authenticated HMAC receipt binds the request bytes and independently observed browser state. The adapter uses a separate Chrome profile with a loopback-only DevTools connection and fixed commands; the phone cannot supply code, shell strings, arbitrary app paths or arbitrary URLs.

This is a documented request/receipt transport rather than a WebSocket relay. It deliberately has no internet relay, cloud device registry or Google identity. Local pairing identifies the explicitly approved phone on that computer; it is not a Google user account or a claim of server tenant isolation. Broad cross-platform app control, Google OAuth/account migration, Gmail/Drive/Calendar, iOS, native desktop UI/installers and production multi-user infrastructure remain separate milestones.

AI calling reuses the existing exclusive microphone and TTS pipeline. Ringing is a visible application state with Answer/Decline; no command mic opens just because an alert rings. Answer explicitly starts or resumes the existing foreground microphone. The call state, real assistant phase, TTS callbacks and actual capture readiness are coordinated. Call limits, stale-ID/generation guards and End prevent indefinite or resurrected sessions. These are in-app AI conversations, without carrier numbers, call-log permissions, or Android unlock bypass.

Dated check-ins use encrypted local records, revision-bound AlarmManager requests, explicit exact/inexact selection and completion tracking. Twenty-percent alerts use actual battery observations and existing retry/quiet/call-safety rules. Both can invite an AI call. First-speaker focus gates one-second PCM windows locally before decoding/timers; it is temporary similarity filtering, not secure authentication or separation of overlapping voices. The owner-only option and encrypted templates remain available.

No automatic Google sign-in button or empty feature modules are added. All 1,500 original requirements and the 1,000/2,000 example corpus are preserved as a tracked backlog. Imported examples do not train a proprietary foundation model. Release reports distinguish software tests, controlled fixtures, compile-only Android instrumentation and tests requiring actual devices.
