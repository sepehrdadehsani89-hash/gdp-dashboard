# Jarvis 4.1 phone and paired-device acceptance

**NOT RUN: no authorized Android device, emulator, Windows computer or iPad is connected to this workspace.** These are acceptance procedures, not passed tests. Automated JVM cases and SDK artifact checks are reported separately. Use a test account and test reminders where possible; never clear storage or uninstall the existing app to make an update appear successful.

1. **Update and data preservation.** Establish the installed package, version code and certificate. The preview updates only the matching `com.jarvis.next.phoenix` signing identity. Update over the known code31 Phoenix APK, record Android's real result, and compare saved settings, provider configuration, voice, wallpaper, memories and granted access. Keep the original application installed. If Android rejects the update, retain its exact `INSTALL_FAILED_*` result using the existing Windows wireless-debugging guide; a pairing code alone does not connect a remote cloud workspace.
2. **Core motion.** With Reduced Motion off, verify the original core advances while idle, listening, thinking and speaking. Exercise foreground/background transitions and Android Battery Saver. Record frame behavior and thermal/battery conditions; unit tests do not prove animation on the Redmi9.
3. **Reduced Motion.** Enable and disable the saved preference, restart, and compare with Android's animator scale and Battery Saver. Confirm the interface, wallpaper and persisted choice survive. No automatic permanent preference change should occur because of temporary system restrictions.
4. **Provider restoration.** Test an explicit real question, backgrounding during renewal, reopening, process recreation and a connection outage. Verify the selected credential mode persists; a valid renewable grant is reused. A catalog or authorization alone must never turn inference green. Reject revoked credentials without deleting unrelated accounts or using another paid provider.
5. **Voice output.** Check a genuine AI answer, battery answer and ordinary local answer through the configured output voice. Test unavailable/private-disallowed voice and playback cancellation. A greeting or preview alone is insufficient evidence that AI answers are spoken. Record the actual voice heard, output consent and any error.
6. **Microphone permission and indicators.** Test initial denial, permanent denial, later grant, Android's microphone privacy switch and process restart. Android must own permission prompts. Capture must follow an explicit user action and show the actual foreground/microphone indicator; installation cannot silently grant access.
7. **Recognition and owner policy.** Test a real wake phrase, a normal utterance, uncertain recognition, absent offline model, another speaker and a canceled command. Confirm the command lab identifies genuine speech separately from typed input. Do not treat a typed test as an ASR test.
8. **Installed-app launch.** Test WhatsApp, Gmail and Chrome with the wake prefix, localized labels, exact aliases, disabled apps, a removed alias target and a work-profile boundary. Exercise foreground dispatch and the required background notification handoff. Verify the actual opened app; a dispatched intent alone does not prove it reached the foreground.
9. **Flashlight.** Test both states, repeated requests, denied Camera permission, an occupied camera and unavailable hardware. Compare the actual torch with the returned status. Failure or missing hardware must not produce a success claim.
10. **Connectivity settings.** Exercise Wi-Fi, Bluetooth, hotspot and Airplane Mode requests on the Redmi9. Check which official panels exist, grant Bluetooth permissions deliberately, and verify actual state after returning. Opening a panel must remain USER_ACTION_REQUIRED until a real supported readback establishes the requested state. Restore the original connectivity settings manually.
11. **Volume and DND.** Test media volume0/40/100percent, mute/unmute, ringer/vibrate and denied Notification Policy access. Compare actual Android stream/ringer state. Grant DND access through Android and verify readback; test cancellation and revocation. Restore the user's previous settings.
12. **Battery and settings-only controls.** Compare reported charging, percentage, temperature/health availability and Battery Saver with Android. Exercise orientation, system theme, reading mode, cast, Quick Share/Mi Share, focus, bedtime and wallet shortcuts. Record unsupported Xiaomi screens. An app-specific orientation request or a settings shortcut must not be reported as a global system change.
13. **Visible screen recording.** Deny then grant a fresh MediaProjection request. Verify the ongoing notification, video-only recording, explicit stop, system stop, lock/process interruption, screenshot exclusivity and fresh consent for a later session. Play the actual saved MP4 and inspect duration. A pending or invalid file must not be called saved. Recording limits are30minutes/512MB; no recording audio is requested.
14. **Lock and secure unlock.** Test absent/enabled lock-only device administration, countdown cancellation and actual locking. Unlock requires Android PIN/pattern/password/biometrics as configured. Test protected Google/notification/calendar commands while locked. No voice, accessibility or model output may bypass the lock.
15. **Google setup and isolation.** Follow [the Google setup guide](GOOGLE_SETUP.md). Test missing project, wrong signing registration, canceled selection, denied scope, independent service consent, account switching during a read and actual successful reads. Compare selected Gmail profile identity with the chosen account. Verify real sender/subject/date/previews, unread-label count and teacher sender filter using known test messages. Check403/401/quota/offline behavior without invented mail.
16. **Google files and indexing.** Read an explicitly approved Docs/Sheets/Slides/Forms ID and reject a different/missing identity. Inspect the bounded output, then explicitly index one permitted snapshot. Restart, review its age, switch accounts and delete snapshots. Verify original cloud files remain and general AI retrieval receives no automatic Google index.
17. **Notification awareness.** Deny listener access, grant it with no permitted sources, select one source, disconnect the listener and revoke source consent. Verify only actual active permitted previews are returned, with protected apps, secret visibility, group duplicates and codes excluded. Confirm a disconnected listener differs from an empty result and a preview count is not called an unread total. No private chat database or historical inbox is queried.
18. **Owned reminders.** Create, edit and cancel unambiguous future reminders; reject vague/past/DST-ambiguous times. Test permission/channel denial, reboot, time/zone change, duplicate worker delivery, editing during delivery and removal during a claim. Delivery is approximate Android work. Compare actual notification posting with status; NOTIFIED does not mean heard/read, and DELIVERY_UNCONFIRMED requires review. The notification must contain a generic prompt, not private reminder text. Existing calendar events and Call Me entries must remain intact.
19. **Farewell and microphone closure.** Use “Goodbye, Jarvis,” “Thank you, Jarvis. I have to go,” English/Spanish/Persian closures and questions about the word goodbye. Test a real pending reminder/calendar event with optional context off/on and private-speech consent off/on. Check speech completion, playback failure, Stop All, cancellation, lock and delayed navigation callbacks. After closure, verify capture actually releases and stays stopped until a new explicit listening action. Verify the optional wake service's real indicator when manually enabled again.
20. **Computer selection and verified actions.** Individually approve each computer's expiring QR on both devices. Exercise distinct names/aliases, all20 registry slots, the21st rejection, re-pairing, offline targets, wrong pins, revocation, target switching while confirmation waits and cancellation during execution. Every action must stay bound to the reviewed device/session. Verify actual Chrome opening/search through authenticated postconditions. Native Windows/macOS behavior, public Google search, Android speech round trips and internet relay require their own runs. Arbitrary shell, unsupported OS controls and iPadOS-restricted functions must never be reported as completed.

Save device model, Android/MIUI version, application version/package/certificate, prerequisites, actual steps, result and redacted evidence for each run. Mark unavailable cases NOT RUN or blocked with their specific prerequisite. Never put account passwords, API keys, tokens, QR secrets or private message bodies in the report.
