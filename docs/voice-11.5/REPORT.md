# Jarvis 11.5 — voice and existing-core repair

This development update changes the existing Android application, package `com.jarvis.next`, version code 21 / `11.5.0-reinstall`. It retains the newer signing line used by 11.4, existing layout/colors/core geometry, charging features, widgets, local AI, configured Fish voices, permissions and stored data. It does not generate a key or migrate the original Jarvis 7.0 signature. Install over a matching newer build; if Android rejects a signature, preserve the installed application and data rather than uninstalling it.

## Voice changes

The wake recorder previously discarded its first complete audio packet after a command-generation change. That packet is now fed into the newly reset decoder. A shared, monotonically issued greeting ticket prevents duplicate/replayed greeting callbacks; a bare wake phrase inside an active follow-up no longer starts another greeting. Existing exclusive microphone leases, permission checks, call/recording-silence handling and lifecycle cleanup remain.

The default greeting is exactly **“Hello sir, how can I help you?”** (with the existing localized equivalents). Optional time-aware greetings remain available in Voice Lab. Greeting playback no longer waits for speaker embedding inference or opens an interruption recorder. Command capture arms after actual playback completion and its echo guard; UI distinguishes microphone preparation from a recorder that has actually started. Other optional playback interruption requires an actually enabled echo canceller; Stop remains available.

A logical voice coordinator records idle, wake, greeting, waiting-for-microphone, listening, processing, speaking, follow-up and error transitions. Generation checks reject stale completion callbacks. Recognition retries are bounded to one per failed turn and do not instruct the user to repeat the wake phrase. Existing inactivity and maximum-utterance limits remain; audio is not restarted indefinitely.

Empty Vosk final results are silence boundaries, not failed understood commands. They preserve accepted final segments and cannot execute an unrecognized partial. Exact harmless device-fact requests and ordinary non-action questions are no longer discarded solely because of a low average word score. Invalid scores and uncertain side-effectful/compound requests remain rejected. Actual uncertain recognition, optional speaker-focus rejection, owner-filter rejection and backend errors have different paths.

Time and date use the actual device clock, locale/time zone and 12/24-hour preference without invoking AI. Existing battery/temperature handlers use Android readings, and existing installed-app matching/launch handlers remain. General questions keep the configured secure provider or installed local model. Sanitized provider HTTP, quota, connection and missing-model failures receive truthful spoken feedback instead of an ASR retry message. No provider key, voice account or successful backend connection is supplied by this release.

Only the two fixed public English/Spanish courtesy greeting clips may be cached privately, keyed to the configured Fish voice/model/account configuration, bounded by size/count and seven-day expiry. Ordinary conversations are not added to this cache. Changing configuration invalidates the lookup; failed greeting playback and explicit erase clear it. A first uncached network greeting still depends on provider latency. Existing private-speech consent stays in force.

## Train and enable the owner-voice filter on your phone

1. Update the matching newer Jarvis installation, open it and unlock the phone.
2. Open **Settings → Rebirth → Set up owner voice · 20-second local recording**. Alternatively, say **“train my voice”** before enabling filtering.
3. If needed, tap **Download optional model**, review the real 26,530,550-byte WeSpeaker model/license, and approve its download. Microphone permission and recording consent are explicit.
4. Enter your name, select **Owner profile**, and check consent. Leave **Enable owner-only spoken commands after training the owner** checked.
5. Tap **Enroll with 20 seconds of speech**, approve recording, wait for the spoken prompt to finish, then speak naturally for 20 seconds. The progress is actual recording progress. Only an encrypted local embedding template remains; raw audio is discarded.
6. Tap **Test a possible match · not authentication**, record a different sentence, and inspect the owner-filter result. If clear owner speech is rejected, review microphone position/noise, add another consenting 20-second sample, or use **Calibrate owner filter · new 5-second sample** with the enrolled owner present. Calibration needs fresh recording consent. Test new phrases afterward, including “what time is it”.
7. Confirm **Accept spoken questions and actions only from the enrolled owner** is on. Test a consenting different speaker as well. Higher match strictness rejects more voices and may reject the owner; it is a cosine threshold, not a probability.

If an owner profile already exists from an earlier build, keep it: use **Add another 20-second sample** under that profile, or test it and enable the owner-only switch directly. You do not need to delete the template or create a second owner.

Each voiced command is checked locally against the owner template before native handlers, app actions or the AI backend execute. The existing microphone supplies the sample; no parallel recorder is added. Samples are transient, at least one second long, and erased after use. Unknown, ambiguous, missing-model and failed matches run no command and give distinct feedback. Versioned, short-lived in-process permits prevent an old match from authorizing a later request or a changed template. Stop and typed controls remain available. Existing private-action Android authentication is still required.

The wake greeting is public courtesy and does not establish identity. This speaker-similarity filter is not secure authentication and cannot guarantee rejection of similar voices, recordings or synthesized speech. It does not unlock Android or bypass device credentials. After a cold process start while locked, unlock once and explicitly start listening to load the encrypted owner template; unavailable verification fails closed. Deleting the owner template or removing its model cannot silently disable an enabled restriction. Encrypted templates can be deleted/retrained in this screen; the filter can be switched off there while unlocked.

## Existing animated core

The original Canvas core, colors, ring geometry and charging visuals remain. Idle rotation is more visible and includes a subtle breathing glow. Listening waveform/rings use real PCM levels with perceptual gain. Fish audio now has an off-main Android MediaCodec decoder that computes only bounded RMS/timestamp bins from the already-authorized private MP3 file. The waveform reads those bins at MediaPlayer's actual cursor, so speed changes, pauses and completion do not use guessed text timing. Existing neural AudioTrack metering remains. This is decoded speech energy, not a measurement of hardware speaker loudness. If Android cannot analyze the audio, speech continues and the UI labels its motion decorative rather than inventing readings. Completion, failure and cancellation stop the meter and discard bins; no extra microphone or permission is added. Thinking orbit motion and actual execution state change motion intensity. Error events produce bounded feedback and recover. Neither a video nor generated fake microphone readings are used.

Frame targets adapt to actual display refresh, Android low-RAM status, thermal state, battery and power saver. Active healthy capable devices target 60 FPS; weak devices use a lower cadence, and heat/power constraints take priority. Idle wallpaper schedules fewer frames; hidden rendering remains paused. App/system reduced-motion settings, animation speed zero and intensity zero remain respected. The HUD shows the reason when app motion is paused and offers an explicit restore control for app settings. No actual Redmi 9 frame-rate measurement was made here.

## Verification and limits

The release's [verification record](../../downloads/voice-11.5/VERIFICATION.md), [machine-readable build identity](../../downloads/voice-11.5/build-info.json) and [frozen input checksums](../../downloads/voice-11.5/source-inputs.sha256) identify the actual build and results.

New regression tests include 20 repeated logical wake → one greeting → capture → timezone-aware time answer → follow-up → truthful backend-failure interactions, stale callbacks, exclusive phase readiness, bounded ASR retries, silence handling, ordinary-question dispatch, local time zones, cache expiry/configuration, owner mismatch/ambiguity, permit expiry/revocation, fresh-sample calibration and adaptive/reduced-motion behavior. Decoded-speech tests cover real PCM16/float buffers, stereo duration, silence, timestamp alignment, unavailable gaps, buffer slices, bounded storage and stale meter ownership. These are JVM tests of the real policies, PCM envelope and coordinator, not acoustic end-to-end Android tests. Android instrumentation sources are compiled separately; compilation is not execution.

An additional host test loaded the actual SHA-256-verified WeSpeaker model and computed embeddings from locally generated synthetic speech, with no human/user recording. Same synthetic-voice phrases scored 0.9301 and 0.9562; different synthetic variants scored 0.8863 and 0.6719. All match the expected result at the strict 0.90 default; the related 0.8863 variant would pass the older optional-hint threshold 0.72. This small exploratory fixture is not a calibrated false-accept/reject study, a phone latency benchmark or replay-resistance evidence. Owner-mode calibration and testing remain necessary on the phone. The [host results](speaker-host-results.json) retain both thresholds and limitations.

No physical Redmi 9 or other Android device was connected for this release. Real microphone/wake latency, Android recognizer callbacks, Fish account/playback, bilingual acoustic recognition, echo behavior, background/lock lifecycle, owner accuracy, lock countdown and measured frame rate still require hardware tests. A host Vosk decoder benchmark could not run because the official model host was denied by the environment network policy; no alternate host was used to bypass that denial.

### Phone acceptance test

1. Keep the selected language speech pack installed and the existing configured output voice working. Review the existing private-speech consent if you want private answers spoken through Fish; without it, the app keeps those replies as text and explains the speech restriction. Check microphone permission, start listening explicitly and say “Hey Jarvis” once.
2. Hear one greeting, wait for actual listening, ask “What time is it?”, and compare the spoken answer with Android's clock.
3. While the follow-up window is active, ask the date and battery without another wake phrase. Ask an ordinary general question; expect an actual configured-backend answer or its truthful failure.
4. Observe visible idle, listening, thinking and speaking motion. If paused, inspect the displayed reason and Android reduced-motion/power settings. Verify returning from another app, screen-off/on and charging preserves the existing features.
5. Enable the trained owner filter, repeat the same sequence and test clear owner/consenting non-owner speech, silence, short commands, model unavailable, template deletion, Stop, typing and process restart. Unknown voices must run no action; protected actions must still use Android authentication.
6. Repeat the complete sequence at least ten times, including one unavailable-backend case and one TTS failure. Check Voice Lab's bounded diagnostics for transitions/errors; no raw recordings, secrets or raw transcripts are persisted in this diagnostic trace. Recognized words remain available in the existing user-visible live captions.

Gmail stays removed as previously requested. The attached 1,500-feature cross-platform master document remains a staged backlog; this release does not claim all of it, commercial readiness, flawless speaker authentication or measured hardware performance.
