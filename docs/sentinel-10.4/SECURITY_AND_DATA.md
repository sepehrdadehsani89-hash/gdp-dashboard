# Screen security and preserved data

Open Settings → Open screen security. Configure a real system screen lock in Android first. Tap **Configure voice unlock · start verification**, then explicitly start each of three Android-owned credential challenges. Jarvis receives only success/cancel callbacks; it neither reads nor stores your PIN, password, pattern or biometric data. The alternative mode clearly labels stages two and three as setup understanding confirmations after one genuine Android authentication. They are not additional authentications.

Only completion enables requests. Wrong/cancelled/stale/replayed callbacks, Stop, lost capture ownership, process recreation, timeout and unavailable device security cannot complete setup. Nonsecret setup metadata does not authorize any later action. Normal credential changes are not detectable through this app's APIs; future unlocks remain Android's decision. Removing the secure screen lock invalidates setup when reconciled.

An exact recognized unlock command requests Android authentication. It cannot unlock using a voice phrase or stored speaker similarity. Foreground presentation requires actual activity focus; otherwise a short-lived public notification asks you to tap. Disabled notifications or background restrictions produce a manual-open instruction. The private activity renders only public authentication status; success requires a real system callback and observed unlocked state. Requests expire after two minutes and do not survive process death. There is no stored private action resumed after unlock.

Optional Android device administration is **force-lock only**. You must review and activate it in Android's own screen. It requests no wipe, password reset or credential policies. Remove it from this settings page or Android device-admin settings. Without it, use your phone's power button. Jarvis reports a lock request separately from observed locked state.

Credential presentation pauses the existing wake/microphone capture and marks a durable, nonsecret privacy pause across process recreation. An interrupted authentication may leave listening stopped. Unlock normally and explicitly restart listening or use the visible interrupted-setup reset; this clears a privacy pause, never authenticates an action. Stop invalidates outstanding capture generations and authorization work.

New contacts are encrypted in the existing feature vault, limited to fifteen, reviewed before saving. Linked Android contact numbers are re-read before dialing; changed, deleted, revoked or inaccessible entries require reselection. Calling opens ACTION_DIAL and requires the user's final Android Call action. No CALL_PHONE or call-log permission is added. Optional READ_CONTACTS supports linked-number rechecks.

Personal voice memos are separate explicit microphone recordings, not recorded calls. Optional READ_PHONE_STATE is used only to reject unknown/active call state, alongside AudioManager state checks during recording. Device/OEM restrictions may prevent reliable capture and are not bypassed. Playback, SAF export and system share are separate user decisions. A dialer return is not an unanswered-call signal. Temporary unshared previews are cleared on leaving; sharing creates a private FileProvider cache copy for the recipient, with copies older than 24 hours removed on the next memo operation. Recipient selection belongs to Android's chooser; Jarvis does not silently send.

Existing package, database, memories and settings stay in place for a compatible signed update. No destructive migration, phone uninstall or data clear was performed. The old memory export is a subset: document text, approved memories, tasks and eligible aliases. It does not back up conversations, credentials, models, output-voice config, contact shortcuts, speaker profiles, memo files, setup metadata, signing identity or every setting. Keep existing installed data and separately selected exports private.

The retained reinstall signing certificate matches the previous reinstall beta, not original Jarvis 7.0. Original 7.0 cannot accept this APK in place without its original private signing key. Android's signer check cannot be bypassed by keeping the package ID. No replacement key was generated. Preserve both encrypted signing backup and separate unlock file privately outside this cloud workspace; neither is included in published source or APK downloads.
